Apache, PHP, MariaDB and Mailpit, in one panel.

SLOPP is an XAMPP-style control panel, rewritten in Rust with a native GPUI interface, for Linux, macOS and Windows. It runs the stock servers your system already has, catches the mail your PHP sends in Mailpit, keeps the whole stack in one folder, and shows what's listening on which port.

Three modules, like XAMPP

Apache, MySQL and Mailpit for mail, without Tomcat or FTP.

SLOPP doesn't bundle the servers: it finds the ones you installed, on PATH and in the usual places, and Settings takes explicit paths. Apache runs PHP through PHP-FPM, or mod_php where PHP has an Apache module. MariaDB gets a database on its first start, and phpMyAdmin or Adminer is downloaded when you ask for it, served at /phpmyadmin/ or /adminer/. PHP's mail() goes to Mailpit, which keeps every message in the stack and shows it in its own web page, so nothing leaves your machine.

Ports default to XAMPP's 80, 443 and 3306, or 8080 and 8443 where your user can't use low ports, and Mailpit's own 1025 for SMTP and 8025 for its page.

What the panel does

One native program, drawn on the GPU by GPUI, the UI framework behind the Zed editor. No Electron and no web view.

Starts and stops each server

One button per module, with its ports, PIDs and a log of what happened. Install gets a missing server with your package manager. Config errors show up with line numbers before Apache starts.

Catches PHP's mail

mail() works with no setup and never reaches a real inbox: Mailpit keeps every message in the stack and shows it at localhost:8025. Try it in the demo above.

Leaves your config alone

Config files are written once and never overwritten. Ports and paths go on the command line at start, so changing a port doesn't touch your edits.

Finds port conflicts

The Ports page shows which program holds 80, 443, 3306, 1025 or 8025, so you know why a server won't start before you go looking.

Lives in the tray

The icon's lamps show what's running: Apache, MySQL and Mailpit, top to bottom. Its menu starts and stops modules and opens the site, phpMyAdmin or Adminer, and Mailpit's inbox.

Keeps servers running

Close the panel and your site stays up, as with XAMPP. Settings can stop everything on quit instead. Restarting into an update leaves them running too.

The real window

Apache on 8080 and 8443 with PHP-FPM, MariaDB on 3306 and Mailpit on 1025 and 8025, after an autostart.

Install

One command installs SLOPP and the servers it needs. After that SLOPP updates itself: it says when a release is out, and Update, then Restart, installs it (Settings → Updates). Running the command again works too. The builds aren't signed, so the scripts check them against the release's SHA-256 checksums.

x86_64, glibc 2.39 or newer

curl -fsSL https://slopp.gs0.me/install.sh | sh

Installs the AppImage to ~/.local/bin, with slopp and sloppctl beside it, then the missing servers: Apache, PHP and MariaDB with apt, dnf or pacman (it asks for your password), and Mailpit from GitHub, since the distributions don't package it. On NixOS, use nix run github:gabors0/slopp instead.

Options after sh -s --
$ curl -fsSL https://slopp.gs0.me/install.sh | sh -s -- --no-deps
--no-deps          SLOPP only, not the servers
--version 0.3.0    a specific release
--dir ~/bin        where the AppImage goes
--yes              don't ask first
--uninstall        remove SLOPP, keep the stack

Rather do it yourself? Download the AppImage or the tarball.

x86_64, Windows 10 or newer. New, so expect rough edges.

irm https://slopp.gs0.me/install.ps1 | iex

In PowerShell. Runs the setup for your user, without admin rights, then installs the missing servers (Apache, PHP, MariaDB and Mailpit) with winget; MariaDB's installer asks for permission. An existing XAMPP's servers work too.

Options with the script as a script block
PS> & ([scriptblock]::Create((irm https://slopp.gs0.me/install.ps1))) -NoDeps
-NoDeps            SLOPP only, not the servers
-Version 0.3.0     a specific release
-AllUsers          for everyone (asks for admin rights)
-Force             reinstall the same version
-Yes               don't ask first
-Uninstall         remove SLOPP, keep the stack

Rather do it yourself? Download the setup or the portable zip; SmartScreen may warn the first time (More info, then Run anyway).

Everything in one folder

Laid out like XAMPP's, in ~/.local/share/slopp (%LOCALAPPDATA%\slopp on Windows). Put your sites in htdocs.

Stack
htdocs/           your sites
apache/conf/      httpd.conf and extras
apache/logs/      error.log, access.log
php/php.ini
mysql/my.cnf
mysql/data/       the databases
phpMyAdmin/       once you get it
adminer/          once you get it
mailpit/          the mail PHP sent
sloppctl XAMPP's lampp, on the same stack
$ sloppctl start [apache|mysql|mailpit]
$ sloppctl stop [apache|mysql|mailpit]
$ sloppctl restart [apache|mysql|mailpit]
$ sloppctl status
$ sloppctl ports      who listens where
$ sloppctl paths      the stack and programs
$ sloppctl install-phpmyadmin
$ sloppctl install-adminer
$ sloppctl install-servers  what's missing

Your machine only

A development stack, set up for convenience, as XAMPP's is.

Not for a network. Like XAMPP, MariaDB's root user has no password, and phpMyAdmin and Adminer log in as root. The servers listen on localhost; don't expose the stack.
