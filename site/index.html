Apache, PHP and MariaDB, run from one panel.

SLOPP is an XAMPP-style control panel, rewritten in Rust with a native GPUI interface, for Linux, macOS and Windows. It runs the stock servers your system already has, catches the mail your PHP sends in Mailpit, keeps the whole stack in one folder, and shows what's listening on which port.

Three modules, like XAMPP

Apache, MySQL and Mailpit for mail, without Tomcat or FTP.

SLOPP doesn't bundle the servers: it finds the ones you installed, on PATH and in the usual places, and Settings takes explicit paths. Apache runs PHP through PHP-FPM, or mod_php where PHP has an Apache module. MariaDB gets a database on its first start, and phpMyAdmin or Adminer is downloaded when you ask for it, served at /phpmyadmin/ or /adminer/. PHP's mail() goes to Mailpit, which keeps every message in the stack and shows it in its own web page, so nothing leaves your machine.

Ports default to XAMPP's 80, 443 and 3306, or 8080 and 8443 where your user can't use low ports, and Mailpit's own 1025 for SMTP and 8025 for its page.

What the panel does

One native program, drawn on the GPU by GPUI, the UI framework behind the Zed editor. No Electron and no web view.

Starts and stops each server

One button per module, with its ports, PIDs and a log of what happened. Install gets a missing server with your package manager. Config errors show up with line numbers before Apache starts.

Leaves your config alone

Config files are written once and never overwritten. Ports and paths go on the command line at start, so changing a port doesn't touch your edits.

Finds port conflicts

The Ports page shows which program holds 80, 443 and 3306, so you know why a server won't start before you go looking.

Lives in the tray

The icon's lamps show what's running: Apache, MySQL and Mailpit, top to bottom. Its menu starts and stops modules and opens the site or Mailpit's inbox.

Keeps servers running

Close the panel and your site stays up, as with XAMPP. Settings can stop everything on quit instead.

Follows your appearance

Dark and light, from Ayu, set in IBM Plex. System follows the OS, or pick one in Settings, as in this page's title bar.

The real window

Apache on 8080 and 8443 with PHP-FPM, MariaDB on 3306 and Mailpit on 1025 and 8025, after an autostart.

Install

One command installs the servers and SLOPP. The builds aren't signed.

x86_64, glibc 2.39 or newer

curl -fsSL https://slopp.gs0.me/install.sh | sh

Installs Apache, PHP and MariaDB with apt, dnf, pacman or zypper, then the AppImage to ~/.local/bin. Mailpit isn't packaged by the distributions: its Install button in SLOPP downloads it. On NixOS, use nix run github:gabors0/slopp instead.

AppImage Tarball

Apple silicon

curl -fsSL https://slopp.gs0.me/install.sh | sh

Installs PHP and MariaDB with Homebrew, then puts SLOPP.app in Applications and clears the quarantine flag. SLOPP's Install button gets Mailpit with Homebrew too.

Everything in one folder

Laid out like XAMPP's, in ~/.local/share/slopp (%LOCALAPPDATA%\slopp on Windows). Put your sites in htdocs.

sloppctl XAMPP's lampp, on the same stack
$ sloppctl start [apache|mysql|mailpit]
$ sloppctl stop [apache|mysql|mailpit]
$ sloppctl restart [apache|mysql|mailpit]
$ sloppctl status
$ sloppctl ports      who listens where
$ sloppctl paths      the stack and programs
$ sloppctl install-phpmyadmin
$ sloppctl install-adminer
$ sloppctl install-servers  what's missing

Your machine only

A development stack, set up for convenience, as XAMPP's is.

Not for a network. Like XAMPP, MariaDB's root user has no password, and phpMyAdmin and Adminer log in as root. The servers listen on localhost; don't expose the stack.
